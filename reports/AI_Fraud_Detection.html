AI-Driven Credit Card Fraud Detection¶

Arch Store | Offline SOC detection engineering lab

An e-commerce SOC needs to prioritize suspected card fraud while keeping legitimate transactions out of the alert queue. This six-cell notebook uses the original ULB/Worldline credit-card benchmark, Random Forest and training-only SMOTE.

The 99.8% figure describes the approximate legitimate share of the raw dataset. The measurable operating target here is at least 99.8% legitimate suppression (specificity) at a fixed 0.50 score threshold, with fraud precision, recall and false negatives reported separately. The threshold is set before evaluation.

Exact duplicate transactions are removed before the stratified 80/20 split. The scaler is fit on training data only. The holdout retains natural class imbalance. This is supervised fraud classification; this dataset cannot establish bot identity.

Run from the project root. First install requirements.txt and run python scripts/download_data.py. Execute all cells in order, or use python scripts/run_notebook.py. Outputs, figures, metrics and HIGH review alerts are saved locally; the dataset and trained model are ignored by Git.

Cell 3 — Prevent leakage and preprocess¶

Remove identical transactions before splitting. Preserve original row IDs for auditability. Fit StandardScaler on training Amount and Time only; reuse it for holdout and future scoring. The PCA components remain in their supplied form.

Cell 5 — Train and save the detection engine¶

Random Forest is a supervised classifier trained on historical fraud labels. The model bundle preserves preprocessing, the fixed policy and package versions.

rf_model = RandomForestClassifier(n_estimators=100, random_state=SEED, n_jobs=-1)

Cell 6 — Evaluate and generate SOC review alerts¶

Evaluate the untouched holdout at the fixed threshold. A high score queues an analyst-review alert; it does not prove fraud or block a customer's payment. Scores from a model trained on SMOTE data are not calibrated probabilities.

Interpretation and next steps¶

Precision measures how many review alerts are real fraud in this holdout; recall measures how many known fraud cases were detected. Specificity measures the legitimate transactions kept out of the queue. Accuracy alone is misleading because an all-normal classifier is already approximately 99.8% accurate.

This historical, anonymized benchmark contains no IP, device, session, payment response or account-login context. It does not demonstrate a live Arch Store bot attack or a production improvement over a firewall. Validate chronologically on recent merchant data, calibrate scores on a separate validation set, choose thresholds against review capacity and loss, and monitor drift before deployment.

Sources: Kaggle dataset, official TensorFlow mirror reference, imbalanced-learn leakage guidance.
